Students run Thonny on their own Mac/Windows laptops.

### GRBL backend notes (applies to both the AX4 and the iDraw 2.0)
- **GRBL has no `M400`.** This matters: it was proven this session that `M400`
  IS the lockstep, because `G1` returns `ok` when the move is *queued*, not
  when it finishes. GRBL behaves the same way but spells the sync as
  **`G4 P0`**. The backend interface therefore needs a "wait for motion
  complete" primitive, NOT a hardcoded `M400`.
- **Pen lift is a servo** (`M3 S<value>` / `M5` via spindle PWM), not a Z move.
  Keep `pen_up()` / `pen_down()` abstract.
- **A cheap GRBL kit likely has no limit switches**, so there is no `G28` and
  no absolute origin: jog to a corner and zero with `G92`. Safer than the MINI
  (nothing to crash), but it becomes a teacher setup step each session rather
  than something a student program does.
- GRBL 0.9 is old (1.1 is current). Fine for `G1` + `G4 P0` + `ok`, but do not
  expect modern GRBL tooling/docs to match exactly.
- What carries over from the MINI work: the serial layer, chatter handling,
  lockstep discipline, config file, SVG/G-code exports, and all 45 tests.
  Student code does not change at all.

### IMPORTANT correction to the brief: iDraw 2.0 is GRBL, not EBB
The brief says "an iDraw (EBB/AxiDraw-compatible) or NextDraw backend". That
was true of **iDraw 1.0**. **iDraw 2.0 uses a Drawcore V2.0 board running
GRBL-compatible firmware** and is NOT EBB/AxiDraw-compatible.

This is good news for the backend work:
- GRBL speaks **G-code with an `ok` handshake**, structurally close to Buddy.
  A GRBL backend reuses most of the serial layer already written and tested.
  EBB (`SM`, `SP` commands) would have been a genuine rewrite.
- Pen lift on GRBL plotters is a **servo** (`M3`/`M5` or an S value), not a Z
  move. That removes the entire pen-mount problem: no float tuning, no
  friction, no added weight, no `pen_offset`, no 34 s homing, no collision
  risk. The backend interface must therefore NOT assume pen up/down is a Z
  move - keep it abstract (`pen_up()` / `pen_down()`), which it already is.
- Trade-off: the AxiDraw software ecosystem (`axicli`, AxiDraw Inkscape
  extension) will not drive it. Irrelevant here since we drive serial directly.
- **Small purchases instead (~$40):** digital calipers (for `pen_offset`, the
  one number still needing real accuracy), low-tack drafting tape (not masking
  tape - it tears paper), a few fiber-tip pens (Micron / Staedtler pigment
  liner) as a control when diagnosing G2 skipping. PTFE (Bowden) tube to line
  the pen guide - friction is the make-or-break variable for a gravity-fed
  floating pen, and printed PLA on plastic is high-stiction. Check for PTFE
  offcuts before buying.
- **Pen holder: free-floating (gravity), not spring-loaded.** A plain vertical
  tube with clearance, pen dropped in, a collar (zip tie) so a shoulder catches
  it on lift. Chosen over a spring because it is the most forgiving option and
  because it removes the homing collision risk: after `G28` the head sits at
  Z2.00, and a rigidly mounted pen protruding >2 mm would be driven into the
  sheet, whereas a floating pen rides up harmlessly. This means student runs no
  longer need a "pen out before homing" rule enforced socially.
- **Pen: Pilot G2.** See the caveats in the Phase 4 section below - it is
  retractable and gravity alone is probably too light for a gel rollerball.
- Consequence for calibration: `pen_down_z` stops being a precise number and
  becomes a band anywhere within the float travel. Phase 4 only has to find
  `pen_up_z` and `pen_offset`.
- Consequence for Z moves: `pen_up_z - pen_down_z` must exceed the float
  distance or the collar never lifts the pen. With ~10 mm float that means
  ~10 mm Z moves per pen lift, which at the current F600 costs ~1 s each way.
  Raise the pen-lift feedrate before the live pen run.
- **Demo shrunk** to `spiral_of(sides=4, count=10, step=8, turn=10)`, basic
  version only. Now fits the paper with no clamping (extent 5-89 mm x,
  44-145 mm y, inside the 0-150 mm paper).
- **Folder reorganisation happens at the end**, not now. Files stay flat in the
  project root until the final tidy-up into `student/` + `teacher/` + `docs/`.

## Hardware safety rules (from the brief - do not violate)
- Never move the printer (home, G1, jog) without asking first and waiting for
  an explicit OK. The teacher will be at the printer, hand on the power switch.
- Before any `G28`, ask for confirmation that the pen is retracted or removed -
  Z-homing can drive the pen into the bed.
- Read-only serial (listing ports, `M115`) is fine once the cable is confirmed
  connected.
- Heaters stay off. Pen up/down are Z moves.

## Gotchas found so far
- `turtle.Turtle` binds `pu`/`up`/`pd`/`down` as aliases at class-creation
  time, so `Plotter` re-binds them after overriding `penup`/`pendown`. Don't
  remove those two lines.
- `connect()` currently calls `G28` itself. That is a collision risk with a pen
  fitted and must be gated behind a confirmation before Phase 3.
- `plotter.py --jog` is interactive; Phase 3 replaces it with a script.
